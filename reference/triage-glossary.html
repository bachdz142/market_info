Triage — Reference

Quick-reference for the triage skill's vocabulary. Print this one out.

What it is

triage moves externally-reported issues (bug reports, feature requests, unannounced PRs) through a small state machine, ending in an agent-ready brief, a question for the reporter, or a closed issue with a recorded reason. It never touches issues you wrote yourself via to-tickets — those are already agent-ready.

The two category roles

RoleMeans
bugSomething is broken
enhancementNew feature or improvement

The five state roles

Every triaged item carries exactly one category role and exactly one state role — never zero, never two at once.

StateMeans
needs-triageYou need to evaluate it — the default landing spot
needs-infoWaiting on the reporter; returns to needs-triage on reply
ready-for-agentFully specified, brief attached — an AFK agent can take it
ready-for-humanSame brief, plus why it can't be delegated (judgment / external access / manual testing)
wontfixClosed, reason recorded

The three wontfix flavors

ReasonWhat happens
Already implementedComment pointing at where it lives — nothing written to .out-of-scope/
Rejected bugPolite explanation, then close
Rejected enhancementA file in .out-of-scope/ (one per rejected concept, not per issue), then close

Before any brief: verify

Bug → reproduce from the reporter's steps. PR → check out the branch, run tests. Outcome is one of: confirmed (with code path), failed to reproduce, or not enough detail to try (→ strongest needs-info signal). Also checks: redundancy (already built?) and prior rejection (does .out-of-scope/ already say no, matched by concept not keyword?).

The agent brief

Durable, not precise: names types, signatures, behavioural contracts — never file paths or line numbers, because the code moves underneath it while it waits.

Where it sits among the other skills

You haveReach for
A tracker full of raw reports from other people/triage
A rough idea of your own, nothing written downgrill-with-docs
A settled conversation to turn into a specto-spec
A spec to split into agent-ready ticketsto-tickets
A confirmed bug that needs a root cause, not a labeldiagnosing-bugs

triage is the on-ramp for inbound work, not a step in the main authoring chain (grill → spec → tickets → implement → review). Both lanes merge at ready-for-agent.

Invocation

Type /triage plus plain language — it never runs on its own. E.g. "show me anything that needs my attention", "let's look at #42", "move #42 to ready-for-agent".
