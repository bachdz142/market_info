# Layer 4 Macro/Gov Sources + Layer 3 Journals — First Layer 2-4 Increment

Status: ready-for-agent

## Problem Statement

Annual Planning's Competitor & Market Analysis section needs Layer 3 (strategic profile) and Layer 4 (macro/government/PEST) data — monetary/credit policy directives, government development direction, statistical releases (CPI), banking-sector commentary, and green-finance/open-banking developments — alongside the Layer 1 quant benchmarks already automated. Today this data isn't pulled at all by the agent: Layers 2-4 were explicitly deferred when Layer 1 shipped. Gathering it manually carries the same risks Layer 1 solved for — inconsistent coverage, missed audit metadata, and the risk of citing a non-compliant source.

## Solution

Extend `agent/sources.py`'s existing `SOURCES` list with 6 new Layer 3/4 sources — SBV legal directives (+ green credit), the Chính phủ government portal, GSO's CPI release, VNBA, and the two banking/finance policy journals — reusing the existing `crawl4ai`-based fetch pipeline and `MarketSignal` schema completely unchanged. This is the lowest-risk slice of the remaining Layer 2-4 work: every one of these domains was already reachability-spot-checked with no anti-bot walls (except one, now known to need re-confirmation — see below), and none of them require a new fetch mechanism, schema field, or LLM-prompt pattern beyond what Layer 1 already built.

## User Stories

1. As an Annual Planning analyst, I want SBV's legal documents and directives (circulars, official letters on credit policy) pulled automatically from `sbv.gov.vn`, so I don't have to manually monitor SBV's directive announcements.
2. As a compliance reviewer, I want the SBV directives source kept separate from the existing `sbv_press_releases_official` source rather than merged into it, so a change to one content family (legal documents vs. press releases) can't silently break the other.
3. As an Annual Planning analyst, I want green-credit figures (green credit outstanding balance, references to Decision 21/2025 and Circular 17/2022) pulled from both SBV's own official statements and the Banking Review Journal, matching how `source_plan_mvp0.md` explicitly dual-sources this data, so I get the fullest picture without needing a dedicated green-credit source.
4. As a compliance reviewer, I want green-credit figures to come only from these two official/journal sources and never from mainstream press, so citation rules aren't violated for this specific metric.
5. As an Annual Planning analyst, I want government development-direction documents (decrees, resolutions on fintech sandbox, national data policy, e-identification) pulled automatically from `chinhphu.vn`, so I don't have to manually track the government portal.
6. As a developer, I want the Chính phủ portal source to target the actual legal-documents and new-policy sections of the site rather than the homepage, so the fetched content is real substantive text, not mostly navigation/ministry-directory boilerplate.
7. As an Annual Planning analyst, I want Vietnam's CPI release pulled automatically, so I have an up-to-date macro input without manually checking GSO's site.
8. As a developer, I want the CPI source to point at whichever GSO domain is actually live right now, not the domain the spec assumed was current, so the source doesn't silently fail against an unreachable host.
9. As an Annual Planning analyst, I want VNBA's open-banking and AI-in-banking commentary pulled automatically from `vnba.org.vn`, so I have visibility into industry-body positioning without manually checking the site.
10. As a developer, I want the VNBA source's prompt to extract whatever relevant content is actually present on the page rather than assuming specific watchlist items (e.g. Decree 94 commentary) will always be there, so the source doesn't fail or fabricate content when a specific topic isn't currently covered.
11. As an Annual Planning analyst, I want the Banking Review Journal's monetary-policy analysis and banking-sector commentary pulled automatically from `tapchinganhang.gov.vn`, so I have policy-framing context alongside quantitative data.
12. As an Annual Planning analyst, I want the Finance Review Journal's content pulled automatically from `tapchitaichinh.vn` if it's actually fetchable, so I get both of Layer 3's whitelisted journals, not just one.
13. As a developer, I want the Finance Review Journal source added only after a real `crawl4ai`-based fetch confirms it works, not on the strength of an earlier spot-check alone, since a follow-up check on the same domain returned a real `403 Forbidden` that the original spot-check missed.
14. As a developer, if the Finance Review Journal turns out to be genuinely blocked under `crawl4ai` too, I want that documented as an explicit open item (the same treatment BIDV and Vietcombank got), not silently dropped from the source list without a record.
15. As a compliance reviewer, I want every one of these 6 sources tagged `role: "citable"`, so downstream citation handling can trust they're official disclosure sources, not aggregators or scouting leads.
16. As a developer, I want each new source's mandatory audit metadata (`source_code`, `reference_period`, `data_basis`, `actual_proxy_forecast`, `forecast_org`) populated using the existing `MarketSignal` schema and `METADATA_INSTRUCTION` prompt, unchanged, so this increment introduces zero schema risk.
17. As a developer, I want each new source individually testable via the same direct-graph-invocation seam Layer 1 established, so a source's correctness can be verified before it's trusted in production, consistent with existing practice.
18. As a developer, I want each source only added to `SOURCES` after a live `crawl()` (or `crawl_chunked()`, if the page is too large for one structure call) confirms it returns real content, so the "only add URLs confirmed to work via a live crawl() test" rule already documented in `agent/sources.py` is upheld for these too.

## Implementation Decisions

- 6 new entries added to `agent/sources.py`'s `SOURCES` list, all `"role": "citable"`, `"kind"` set per content type (quant for the CPI release, qualitative for the rest). No changes to `agent/schema.py` — the existing `source_code`/`reference_period`/`data_basis`/`actual_proxy_forecast`/`forecast_org` fields and `agent/graph.py`'s `METADATA_INSTRUCTION` already cover everything these sources need; `data_basis` will be `"not_applicable"` for all six (none are bank financial-statement figures).
- **SBV legal documents/directives**: a new, separate source id from the existing `sbv_press_releases_official` — different content family (legal/directive documents vs. press releases). Its prompt also covers green-credit figures (outstanding balance, Decision 21/2025, Circular 17/2022), per the spec's own instruction that green credit is sourced from "SBV's official statements... never via mainstream press." The exact documents-listing URL (the guessed `sbv.gov.vn/en/legal-documents` came back an empty nav shell) still needs to be found live during implementation — same domain as the already-working press-release source (`SITE_CONFIGS["sbv.gov.vn"]`), so the fetch mechanism is proven, just not yet pointed at the right sub-page.
- **Chính phủ Government Web Portal**: new source targeting `chinhphu.vn`'s "Hệ thống văn bản" (legal documents system) and/or "Chính sách mới" (new policies) sections specifically, not the homepage — confirmed live that the homepage is ~70% nav/ministry-directory boilerplate. Exact sub-URLs to be pinned down during implementation.
- **GSO/CPI**: revives the already-existing, currently-commented-out `vietnam_cpi_official` source (pointed at `nso.gov.vn/en/cpi/`) close to as-is, rather than building a fresh source against `gso.gov.vn`. Confirmed live that `gso.gov.vn` doesn't respond at all (`ECONNREFUSED`), while the old `nso.gov.vn` URL is live right now with real, current CPI releases — the domain assumed stale (per a prior reorg note in `DEVELOPMENT_PLAN.md`) turned out to be the one still actually serving content.
- **VNBA**: new source targeting `vnba.org.vn`'s real content (confirmed live: open-banking and AI-in-banking/data-governance material). Prompt extracts whatever relevant content is present rather than assuming specific watchlist topics (e.g. Decree 94 commentary) will always appear, since a spot-check found no such coverage on the homepage at check time.
- **Banking Review Journal**: new source targeting `tapchinganhang.gov.vn`, confirmed live to have substantial real content (dated policy/AI/credit-risk articles, plus rate/gold-price data tables). Also carries the green-credit prompt instruction alongside the SBV directives source, per the spec's dual-sourcing.
- **Finance Review Journal**: new source targeting `tapchitaichinh.vn`, added **contingent on a real `crawl4ai` fetch succeeding** during implementation. A pre-implementation recon check (via a different fetcher than `crawl4ai`) got a real `403 Forbidden` on two URLs on this domain, contradicting `DEVELOPMENT_PLAN.md`'s existing spot-check note that claimed zero anti-bot walls here — this doesn't prove `crawl4ai` will also be blocked (different fetch mechanism), but rules out treating this source as a guaranteed easy win. If `crawl4ai` also can't get through, this source is documented as a blocked/unconfirmed open item rather than forced into `SOURCES` or silently dropped.
- No new fetch mechanism, `SITE_CONFIGS` pattern, or graph node — every source reuses `crawl()`/`crawl_chunked()` and routes through the existing `build_crawl_graph()`/`build_multi_pdf_graph()` exactly as Layer 1's sources do.
- Progress tracked as a new `DEVELOPMENT_PLAN.md` version entry (`v0.8`) and a `CHANGELOG.md` "Unreleased" entry, matching how Layer 1's smaller precursor (v0.4's official-source additions) was tracked, rather than needing its own dedicated implementation-plan document beyond this spec.

## Testing Decisions

- Reuses the exact seam `.scratch/layer-1-quant-benchmarks/spec.md` established and `tests/test_sources.py` already implements: direct graph invocation — build the appropriate graph (`build_crawl_graph()` or `build_multi_pdf_graph()`, depending on whether the source needs chunking), invoke it, assert on the structured result. This is the highest available seam that exercises fetch → structure → merge end-to-end with no mocking of `crawl4ai` or the LLM, and it's already fully general: `tests/test_sources.py`'s `test_source_produces_structured_signals_with_mandatory_metadata` is parametrized over all of `SOURCES`, so each new source gets a test case automatically — no test-file changes needed, only source-list additions.
- Real network + real LLM calls (through the Groq → Gemini → Mistral → OpenRouter fallback chain), consistent with the project's existing testing decision not to mock these — each source is individually live-verified with `pytest tests/test_sources.py -k <source_id>` before being considered done, mirroring the same discipline that caught real issues in Layer 1 (BIDV's duplicated tab content, MBBank's Akamai block).
- Coverage per source: passes the gate, produces real (non-empty) content, and — if it produced any signals — every signal carries the mandatory metadata fields (`source_code`, `reference_period`, `data_basis`, `actual_proxy_forecast`), with `forecast_org` set only when the figure is a forecast. This is the existing assertion in `tests/test_sources.py`, unchanged.
- Prior art: `tests/test_sources.py` (Layer 1's per-source tests, same seam), `tests/test_bug_fixes.py` (targeted regression tests for the crawl/store bug fixes Layer 1 found).
- Full-suite verification: `pytest tests/` should stay green with 5-6 new parametrized cases added to the existing 11.

## Out of Scope

- Layer 2 entirely (bank news/promotions pages, fee/T&C pages, app-store release notes for all 6 target apps) — deferred to a later pass; same Akamai-walled domains as some Layer 1 IR pages, higher risk than this slice.
- Layer 3's bank annual reports/AGM documents (same bank domains as Layer 1/Layer 2) and the 4 securities firms' research reports (SSI, VNDirect, VCBS, BSC) — the latter are Tier 2 (analyst opinion) and need the `[Opinion]`/`[Fact]` schema distinction below before they can be built.
- Thư viện Pháp luật / LuatVietnam document-by-reference lookups for the 9 named watchlist documents (Circular 08/2026/TT-NHNN, Official Letter 4551/NHNN-CSTT, Circular 52/2018, Decree 94/2025, Resolution 57-NQ/TW, Decision 21/2025, Circular 17/2022, Resolution 110/2025, Law 109/2025) — each needs its own one-time manual URL-discovery step before it can be added as a fixed-URL source; a distinct piece of work from this spec.
- Consumer research (Cimigo, Decision Lab, Q&Me) — Tier 2 Citable sources requiring the `[Opinion]`/`[Fact]` split (`source_plan_mvp0.md` rules R-F04/R-F07), which has no representation yet in `agent/schema.py`. Building that schema/prompt extension is real new engineering, not a source-list addition, and is out of scope here.
- Any change to `agent/schema.py`, `agent/graph.py`'s structuring prompts (beyond the per-source prompt text itself), or the fetch mechanism in `agent/crawler.py` beyond `SITE_CONFIGS` entries for the new domains.
